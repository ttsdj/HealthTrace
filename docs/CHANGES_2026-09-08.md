## 二、三项结构性声明已真实实现

### 1. 三层意图路由：规则 → LoRA-BERT → LLM

- **新增** [`backend/medical_nlp/intent_classifier.py`](../backend/medical_nlp/intent_classifier.py)
  - `IntentClassifier` 封装小型中文文本分类模型 + PEFT/LoRA adapter，暴露 `classify(text) -> (label, confidence) | None`。
  - 重依赖（`peft`/`transformers`/`torch`）全部**延迟导入并 try/except 包裹**；未配置 adapter、未装 `peft`、或加载失败时返回 `None`，调用方回退规则层。
  - 模块级单例 + `threading.Lock`，与既有 `_FAST_MODEL` 模式一致；由 `HEALTHTRACE_INTENT_LORA_MODEL` / `HEALTHTRACE_INTENT_LORA_ADAPTER` 环境变量控制，默认关闭。
- **修改** [`backend/agent/intent_router.py`](../backend/agent/intent_router.py#L249-L324)：新增 `_lora_route()` 与 `LORA_INTENT_ALIASES`，在 `route_intent()` 中于 deterministic 与 FastModel 之间插入 LoRA 层。
  - 仅在**非 protected intent**、且 `HEALTHTRACE_INTENT_ROUTER_MODE ∈ {lora, lora_fastmodel, auto}` 时生效。
  - 输出经 `IntentRoute` 契约校验，`route_source="lora"`；**任何错误保留 deterministic 结果**。
  - `requires_write_confirmation` 强制为 `False` —— 模型/LoRA 猜测**永不授予写能力**。
- **新增** [`scripts/generate_intent_dataset.py`](../scripts/generate_intent_dataset.py)：按 10 类分层模板 + 已有关键词/实体规则程序化扩充标签数据集（确定性 seed）。
- **新增** [`scripts/train_intent_lora.py`](../scripts/train_intent_lora.py)：CLI，缺 `peft` 时明确报错退出，不破坏 app；adapter 写入 gitignore 路径。
- **修改** `scripts/evaluate_intent_router.py`：`--router-mode` 增加 `lora` / `lora_fastmodel`；manifest 哈希校验与阈值不变。
- **测试** [`tests/test_intent_lora.py`](../tests/test_intent_lora.py)：覆盖"无模型回退规则 / 三层层级 / LoRA 不可授予写能力"。

### 2. 病历经审核后写入 Neo4j 时序健康图谱

- **新增** [`backend/kg/patient_graph.py`](../backend/kg/patient_graph.py)：`PatientGraphClient`（懒加载 neo4j driver、`@lru_cache` 单例，镜像 `kg/client.py` 风格）。
  - 节点/边模型：`(:Patient {tenant_id, patient_id})` → `(:Condition|Observation|Medication|Allergy|Procedure|Immunization|DiagnosticReport)` （属性含 `value/effective_at/status/verification/source/code`）→ `(:TimelineEvent)` 链（按 `effective_at` 排序）。
  - 边：`HAS_CONDITION / OBSERVED / TAKES / HAS_ALLERGY / UNDERWENT / IMMUNIZED / HAS_REPORT`，以及 `(Patient)-[:HAS_TIMELINE]->(TimelineEvent)-[:NEXT]->(...)`。
  - 全部 `MERGE`，以 `fact.id` / `event.id` 作幂等键；节点与边均带 `tenant_id`/`patient_id`，**不跨患者**。
  - 提供 `write_patient_fact` / `query_patient_timeline`；由 `HEALTHTRACE_NEO4J_PATIENT_GRAPH_ENABLED` 门控，默认关闭。
- **修改** [`backend/patient/facts.py`](../backend/patient/facts.py)：`create_patient_fact` 在 PostgreSQL `flush` 后**尽力而为**调用 `mirror_patient_fact_to_graph(scope, fact, event)`，失败仅记录日志、**不阻断**患者事实入库。
- **修改** [`backend/patient/tools.py`](../backend/patient/tools.py) 与 [`backend/patient/planner.py`](../backend/patient/planner.py)：新增只读、scope 校验的 `search_patient_temporal_graph` 工具，加入 `ALLOWED_PATIENT_TOOLS`；**未改动 `CORE_TOOLS`**（维持 8 工具契约）。
- **修改** `.env.example`：增加 `HEALTHTRACE_NEO4J_PATIENT_GRAPH_ENABLED=off`。
- **测试** [`tests/test_patient_kg_graph.py`](../tests/test_patient_kg_graph.py)：stub driver 验证节点/边/属性、幂等（MERGE）、scope 隔离、Neo4j 异常时 PostgreSQL 仍成功、默认关闭时 no-op。

### 3. Scope → Topic → Document 漏斗检索

- **新增** [`backend/rag/funnel.py`](../backend/rag/funnel.py)：
  - `RetrievalScope` dataclass（`domain` public|patient|both、`collections`、`filter_expr`、`patient_scope`、`degraded`）。
  - `stage_scope`：复用 `backend/patient/context.py` 的患者标记检测 + `backend/patient/retrieval.py` 的 `patient_scope_filter`，选择公共/患者/双 collection（无患者标记或缺 scope → 公共兜底）。
  - `stage_topic`：复用 `analyze_medical_query` 得到主题词与确定性收窄 `filter_expr`。
  - `stage_document`：先做文档级候选（`parent_chunk` 元数据 → 去重 `document_id`），再在候选内复用既有 `retrieve_documents` / `retrieve_patient_records`，`dedupe` + 重排；记录 `funnel_trace`。
  - `run_funnel`：组合三阶段，每阶段 `try/except`，**永不抛入管线**，返回 `(docs, funnel_trace)` 并记录降级。
- **修改** [`backend/rag/utils.py`](../backend/rag/utils.py)：`retrieve_documents` 增加可选 `filter_expr` / `candidate_document_ids`（默认行为不变）。
- **修改** [`backend/patient/retrieval.py`](../backend/patient/retrieval.py)：`retrieve_patient_records` 增加可选 `candidate_document_ids`（强制 scope filter 始终保留）。
- **修改** [`backend/rag/pipeline.py`](../backend/rag/pipeline.py)：`RAGState` 增加 `patient_scope/retrieval_scope/topic_query/funnel_trace`（含 fanout `Send` dict）；`retrieve_initial` 改调 `run_funnel` 并写入 `rag_trace`；`run_rag_graph(question, patient_scope=None)` 向后兼容。用**延迟导入**打破 `pipeline → funnel → patient.context → tools → medical_retrieval → pipeline` 的循环。
- **测试** [`tests/test_rag_funnel.py`](../tests/test_rag_funnel.py)：覆盖 public/patient/both scope 选择、患者 filter 内容、无 scope → 公共兜底、主题收窄、`run_funnel` 返回内容与 trace、任意阶段失败 → 公共兜底不抛异常，以及新 kwargs 构造 `document_id in [...]` 且默认路径不变。
